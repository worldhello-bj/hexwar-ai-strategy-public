# 离线裁决引擎

## 一、它是什么

`engine/` 是一个纯 Python、无外部依赖的兵棋裁决引擎，实现了手册第 4 章的推演规则
与第 5 章的裁决表。它通过 `offline/engine_bridge.py` 接到本地桩服务器上，
**让官方前端在完全离线的情况下真正可被指挥**。

```
engine/
├── geometry.py   六角格几何（mapid ↔ 行列、邻接、距离、hexid）
├── equip.py      装备库（data ID ↔ 武器/射程/弹药类型/装甲/权重/侦察范围）
├── crt.py        战斗裁决表（攻击等级 → 掷骰 → 战果）
├── tables.json   裁决表数据（由 tools/build_crt.py 从手册重建）
└── game.py       对局状态机：机动、通视、观察、堆叠、射击、夺控、时钟
```

## 三、已实现的规则

| 规则域 | 实现 |
|---|---|
| 机动 | 徒步行/车辆行的地形与坡度系数、过河减速、车辆禁行/高差限制、冲锋与疲劳 |
| 堆叠 | 同格本方地面单位上限 4，超限拒绝进入 |
| 通视 | 高看低原则、观察点高程 +1 等级、连线线性插值、居民地/丛林地 +1、相邻格必通视 |
| 观察 | 按目标类型取侦察范围，掩蔽/居民地/丛林地减半 |
| 直瞄 | 表1/表2 取攻击等级，表3 高度差修正，表5/表7 状态与防护修正，表6/表4 出结果；**两颗骰**：随机数1 → 表4/表6，随机数2 + 状态修正 → 表5/表7，`最终战果 = crt.combine_result(战斗结果, 修正结果)`（加法在**消灭数**上：空白格 = 消灭 0，正修正直接抬升——`无效 + 1 = 消灭 1`，实测 #129365） |
| 压制 | 150 秒后自动解除；被压制者不能机动与射击 |
| 手雷 | 表8 独立结果表 |
| 反无人机 | 表9/表10；防空武器不可打巡飞弹，巡飞弹不可被任何武器打击 |
| 夺控 | 到达夺控点且本格与相邻 6 格无敌方地面单位 |
| 计分 | `remaining + captured + killed`，分项名与线上 `Report_All.asp` 一致（夺控点 / 剩余兵力 / 歼灭对手兵力）。**三项分值均已平台实测**：`remaining = Σ上阵(score×blood) + Σ车内载员(score×编制)`（对 7527 开局**精确命中红 354 / 蓝 234**，`tools/hex_score_audit.py` 的断言）；`captured = 主要 80 / 次要 50，一次性`；`killed = Σ(损失兵力 × score)`（与 remaining **逐点互补**）。载员归属用**载具 ID**——载入时按 `son` 图标 ↔ 载员 `ico` 固化，不靠会变旧的 `pos2`。`total`（平台式）与 `verified`（只算已实测项）**分开两个数**，**奖励默认用 `verified`**，需显式 `--scoring platform` 才用 `total`。**夺控边界（失守扣分 / 重夺加分）也已实测**，`PENDING_RULES` 现已为空。见 `docs/计分规则待确认.md` |

## 四、接口契约（照官方客户端实现）

| 端点 | 引擎行为 |
|---|---|
| `User_Get.asp` | 动态返回 `Time1` / `RoomSecond` / `ServerTime`，字段顺序与线上一致 |
| `RoomStart.asp` | 置 `Time1=1`，返回 `Time1,WarDateTime,StartTime,..` |
| `RoomStat.asp` | 已开始则返回 `Time1,WarDateTime,StartTime`；未开始返回空 |
| `ObjAjax.asp` | 下发全量单位状态，键顺序与 `ObjUpdate(...)` 的参数表一一对应 |
| `com/ComPost.asp` | 接收指令；成功返回空串（客户端据此判定成功） |
| `com/ComAjax.asp` | 返回 `ComID\|flag\|{JSON}\|时间\|尾部`，客户端据此本地播放动画 |
| `com/updatePos.asp` | **返回本格机动耗时（毫秒）**，客户端据此决定动画速度 |
| `com/MoveEnd.asp` | 返回空串 = 继续机动 |
| `com/Attack.asp` | 执行完整裁决；返回非空 = 射击成功，战果经下一帧 `ObjAjax` 下发 |
| `com/CityTake.asp` | 夺控判定 |
| `Report_Attack.asp` | 返回最近一条战报（含攻击等级、随机数、修正与战果） |
| `ObjInfo.asp` / `Obj_Weapon.asp` | 由引擎实时生成装备面板 |
| `com/TgList.asp` | 官方此接口 404；引擎给出可用实现 |

## 五、怎么用

```powershell
py -3.13 d:\兵推\offline\server.py     # 默认 HEXWAR_LIVE=1，引擎接管
$env:HEXWAR_LIVE=0; py -3.13 d:\兵推\offline\server.py   # 纯快照模式（只读复现）
```

浏览器打开 <http://127.0.0.1:8080/>，点「推演开始」即可指挥。

## 六、自检与验证

```powershell
py -3.13 tools\selftest_engine.py   # 几何/通视/机动/裁决/夺控 单元自检
py -3.13 offline\server.py           # 另开一个终端起桩服务
py -3.13 tools\verify_e2e.py        # ★ 端到端：走官方 HTTP 契约，任一项 FAIL 则 exit 1
py -3.13 tools\verify_live_crttables.py   # ★ 线上实测裁决逐条对账（需 7527_transport_capture/）
```

`analysis/engine_selftest.md` 与 `analysis/e2e_verify.md` 是最近一次结果
（当前：selftest exit 0；e2e **6/6**）。

★ `verify_e2e.py` 走的是一条**完整链**，不是接口连通性测试：
选一对「射手有可用武器」的敌我配对 → 反例（17 格不通视开火，接口受理但无战果）
→ 按官方机动链（`ComPost` → `updatePos` → `MoveEnd`）把射手推进到相邻格
→ `com/ObjWeaponReady.asp` 复位武器 → `com/Attack.asp` 真裁决 → `ObjFire.asp`
→ 比对 `ObjAjax` 的 `blood`/`keep` 与 `Report_Attack.asp` 战报。

> ⚠️ 旧版只发 `ComPost{"attack":…}`（那只是**下命令**）而不调 `com/Attack.asp`，
> 所以报告恒为「战果生效: 否」；那是脚本只走了一半链路，不是引擎的问题。
> 现在单发实测：便携导弹 @1 格 → `Attack.asp` 返回 `1`、目标兵力 4→3、`keep=1`，
> 战报里带完整裁决式：`表4[攻击等级7][随机数1 5]=1；表5[复合装甲][修正后6]=+0；最终=1 → 消灭1，压制`。

★ **实测对账（最强的一条证据链）**：`tools/verify_live_crttables.py` 把练习服抓到的
**86 条真实裁决**（车辆 70 / 人员 16）拿来与引擎逐条比：战斗结果、修正结果、最终战果
三条链路**零残差**（有残差则 exit 1）；反解脚本 `tools/derive_table4_columns.py` 用这些样本
反推表格列号（PDF 网格不可信）；回归锁 `tests/test_crt_live.py` 冻结了关键样本。
细节见 `docs/规则符合性.md`「线上实测对账」。

## 七、已知不足

1. **表4（对车辆战斗结果）**：PDF 的表格网格存在歧义，列对齐无法唯一确定。
   ⭐ 已用**线上样本反解**校正了最关键的一格：**攻级10 的列号 13 → 17**
   （列 16/17 在所有随机数行取值相同，取 17 与 units=3/4 一致）；
   攻级 7、9 与现映射相容；**攻级 1–6、8 尚无足够样本，仍是 PDF 值**。
   `tables.json` 里保留了原始数据与 `note`，可对照手册第 29 页人工复核。
2. **弹药与补给**：目前只做消耗，未实现补给/再装填。
3. **同格交战、无人机滞空高度、巡飞弹巡飞时长、无人战车隶属**等规则已建模但未接入自动化时序。
4. **AI**：未实现，`com/CommandCtrl.asp` 为空实现。
5. 引擎的随机数用 Python `random`，与官方服务端的随机源不同，
   因此**单次裁决结果不会与线上逐次一致**，只有概率分布一致。
