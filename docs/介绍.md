# 项目介绍

## 一句话

把一个只有"人在浏览器里对点"的在线兵棋平台，变成**AI 可以编程操控、批量试错、
搜索战术**的离线推演环境。

## 起因

网络兵棋平台通常是 B/S 架构：浏览器负责画图和收键鼠，**规则与裁决全在服务器**。
这对训练很不利：

- **不可离线**：断网或服务器忙就用不了
- **不可批量**：一局几十分钟，要有人在对面陪练，没法跑上千局
- **不可编程**：没有 API，AI 无法接入，只能靠人拍脑袋试战术

而"找好策略"本质上是个**搜索问题**：需要能快速开新局、能枚举选项、
能立刻拿到结果、能大规模重复。所以关键不是"把界面抄下来"，
而是**把裁决逻辑变成可调用的函数**。

## 思路

### 1. 先分清"决策"和"渲染"

在线平台的客户端其实是个渲染器。真正决定胜负的是服务端在收到指令后做的判定。

所以第一件事是**认出裁决边界**：哪些量是客户端算的（几何、通视显示），
哪些必须问服务端（战果、压制、夺控）。认清了才知道要复刻什么。

结论：客户端自己算的只有**几何与可见性**，**战果与状态全在服务端**。
那我们要复刻的核心，就是服务端那一套判定。

### 2. 把"规则"变成"表 + 函数"

规则来自两处，各有各的坑：

- **客户端脚本**：给出接口契约（参数、返回值、单位），但不给判定逻辑
- **比赛手册 PDF**：给出规则叙述与裁决表，但表格是排版的、不是数据

做法是把它们分开处理：

- **数值表**（攻击等级、战果、修正）→ 编码成 JSON 数据文件，引擎读表
- **叙事规则**（"某地形减半""某状态持续 N 秒"）→ 编码成判定函数

好处是数值可替换、规则可单测，两者互不干扰。

### 3. 用"不变量"验证重建结果

从 PDF 重建表格时，纯文本抽取的列结构**必然错位**。不要靠肉眼对齐，
而是**先想清楚这张表在语义上必须满足什么**，再写断言：

- 攻击等级表：射程越远，等级不应升高
- 战果表：攻击等级越高，战果不应变差
- 修正表：高度差越大，修正应越负

用这些不变量不仅能**发现**抽取错误，还能**反解**出正确的列偏移。
实在无法唯一确定的表，就老实标注"存在歧义、建议人工校正"，
而不是假装已经还原成功。

### 4. 把环境做成"标准 RL 接口"

最后一步是**降低使用门槛**。环境暴露四个方法：

```
reset(seed)  → 观察
observe()    → 当前态势（纯 JSON）
legal_actions() → 当前合法动作
step(action) → (新观察, 奖励, 结束?, 信息)
```

之所以坚持**纯 JSON**：这样 LLM 可以直接读写，不用为了接入模型再写一层适配。
之所以坚持**`legal_actions()` 枚举**：把规则约束一次性封装好，
调用方（无论人、脚本还是 LLM）就不会产出非法动作。

奖励用"净胜分增量"，天然稠密。⚠️ 三个分项的**分值都已在真实房间里实测**
（`remaining` 精确命中平台 354/234；`captured` = 主要 80 / 次要 50 一次性；
`killed` = `Σ(损失兵力×score)`），所以奖励不再含任何拍脑袋的数。
三个分项的分值与**夺控边界**（失守扣分、重夺加分）**都已实测**，`PENDING_RULES` 为空；
仍无依据的只剩**终局结算**（时间奖励、平局判定）。见 `docs/计分规则待确认.md`。

### 5. 把"怎么用"写成 skill

环境有了，但一个 AI"会不会用"取决于它知不知道：

- 观察里哪些字段是**过期的**（敌方已知位置不可据此瞄准）
- 哪些动作**看起来能做其实做不了**（被压制、弹药耗尽、不通视）
- 机动是有**时间成本**的，要把剩余时间当预算
- 先抢点、再集火、能压制就压制的**优先级**

这些是"操作性知识"，不是代码能表达的，所以单独做成 skill 交给 AI。

## 交付物

| 组成 | 作用 |
|---|---|
| `engine/` | 裁决引擎：规则 + 裁决表 → 可调用的判定函数 |
| `env/` | 策略搜索环境：标准接口、参考智能体、跑分台 |
| `skill/hexwar-operator` | **操控算子**的 skill：态势判读、动作语义、战术原语 |
| `skill/web-wargame-offline` | 逆向方法论 skill：本仓库的"施工记录"，可迁移到同类平台 |
| `offline/` | 离线客户端：官方前端 + 本地裁决，可鼠标实操 |
| `samples/demo` | 自带合成想定，保证他人克隆即可运行 |

## 能做什么

- 让 AI 批量试不同打法，看哪种净胜分高
- 把环境当 RL 训练场（动作离散、状态结构化、奖励稠密）
- 当 LLM 的规划器沙盒，研究"提示 → 决策 → 反馈"闭环
- 人工通过官方界面实操，边打边看引擎的判定细节

## 不能做什么

- **不能复现官方单次裁决结果**。随机源不同，只有概率分布一致。
- **不能用于作弊**。不得代打、不得冒名参赛、不得用于正式比赛。
- **不能替代裁判**。这是训练工具，不是官方系统。

## 使用边界

- 只使用**使用者本人的账号**，只做正常登录与观察，不绕过任何安全机制
- 抓到的会话信息与凭据**永不**进入代码、日志或提交
- 第三方资源（客户端脚本、美术资源、手册）**不随仓库分发**
- 具体见仓库根目录的 `NOTICE`
