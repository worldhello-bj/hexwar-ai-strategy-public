# 从压缩 JS 提取客户端契约

## 1. 不要美化整个文件

压缩 JS 通常几百 KB、单行几万字符。正确做法是**按需抽取**：

- 列路径引用 + 出现次数 → 知道有哪些接口
- 对每个接口取**调用点前后 200 字符** → 知道大致用途
- 对关键函数按名字抽取（花括号配对）→ 落成单独小文件再读

```python
def extract(name, js):
    m = re.search(r"function\s+%s\s*\(" % re.escape(name), js)
    s = js.rfind("function", 0, m.end())
    # 跳过参数表
    i = js.find("(", s); depth = 0; j = i
    while j < len(js):
        if js[j] == "(": depth += 1
        elif js[j] == ")":
            depth -= 1
            if depth == 0: break
        j += 1
    k = js.find("{", j); d = 0; e = k
    while e < len(js):
        if js[e] == "{": d += 1
        elif js[e] == "}":
            d -= 1
            if d == 0: break
        e += 1
    return js[s:e+1]
```

抽取前先按 `;` `{` `}` 粗略断行，可读性就够用了，**不要**上完整的 beautifier。

## 2. 契约就在 `success:` 回调里

逐个记录：

| 要记录的 | 为什么 |
|---|---|
| 返回值类型（字符串 / JSON / HTML 片段） | 决定桩服务发什么 `Content-Type` |
| 分隔符与字段顺序 | 顺序错就全错 |
| 成功与失败的判据 | 例如"空串=成功""非空=失败" |
| 单位 | 秒还是毫秒、格还是像素 |
| 副作用 | 回调里是否还会触发**另一次**请求 |

**典型模式速查**

| 回调写法 | 含义 |
|---|---|
| `success: function(a){ a ? alert(a) : ok() }` | 空串 = 成功，非空 = 错误信息 |
| `if(0 < v){ ...动画... } else { 失败 }` | 返回**数值**，0 = 不能执行 |
| `a.split(",")` 后按下标取 | 逗号分隔的定长字段串 |
| `a.split("&")` 再 `split("\|")` | 双层分隔的指令/事件队列 |
| `$.each(a, function(k,v){...})` 且 `a=eval("("+a+")")` | 返回的是 **JS 对象字面量**（可能非严格 JSON，例如带尾逗号）|
| `success: function(a){ if(a){...} }` | 空串 = 无事件（轮询空闲）|

**非严格 JSON 要宽容解析**：服务端常返回 `{...},` 这种带尾逗号的字面量。
先 `re.sub(r",(\s*})", r"\1", t)` 再 `json.loads`。

## 3. 字段顺序 = 函数参数顺序

轮询接口常这么写：

```js
$.each(a, function(k, c){
  ObjUpdate(k, c.uid, c.color, c.pos, c.pos2, c.rot, ...);
});
```

那么桩服务返回的 JSON **键序必须与 `ObjUpdate` 的参数表逐位对应**。
把 `function ObjUpdate(` 的参数名列表抄下来，与返回键逐一对照，别凭感觉。

## 4. 找到"权威状态"

在客户端里搜轮询定时器：

```python
re.finditer(r"setInterval\s*\(\s*\"?(\w+)\(", js)
```

找到被定时调用的函数，看它的 success 回调是否**覆盖式**写属性：

```js
p.attr("blood", k); p.attr("pos", e); ...
```

如果是，则**服务端是唯一权威**——你只要把这个接口实现对，
官方前端就会忠实地渲染你的状态。这是最高性价比的切入点。

## 5. 找出"动画由谁播"

看指令下发的返回：

- 若客户端拿到路径后**自己**用 `setInterval` 插值移动 DOM，
  那么服务端只需要返回**本步耗时**，动画白拿。
- 若客户端等下一个轮询帧才更新位置，那服务端返回空即可。

判断方法：搜 `setInterval(function(){ ... left: ... top: ... })` 之类的位置插值。

## 6. 参数里藏着"派生量"

客户端会把**本地算出来的**量一起回传（距离、朝向、高度差、堆叠标记）。
这说明客户端自己也做了一部分判定。移植时要：

- **要么**照抄客户端的本地计算（保证一致）
- **要么**服务端自己重算一遍（更稳，但要确认口径一致）

建议：**服务端重算并在返回值里体现**，客户端的本地值只当提示。
