# 在线兵棋平台 → 离线裁决引擎

## 何时用这个 skill

用户说"想研究某兵棋站的结构""抓下来离线练""做一个能对打的离线版本""从手册还原裁决规则"
"备战某兵棋比赛"，或者给了 `.har` / 站点地址 / 比赛手册 PDF 时。

**先确认三件事**，缺一件都要先问：

1. 是**用户本人的账号**吗？（只允许本人账号，不允许代登录他人账号）
2. 允许通过本人账号的**正常登录与操作**观察系统行为吗？
3. 抓到的数据打算怎么用？（只自用 / 要公开发布 → 决定后面哪些能进仓库）

## 核心判断（先想清楚，能省一半功夫）

**先判断"权威在哪"**。B/S 兵棋通常分两类：

| 类型 | 特征 | 离线策略 |
|---|---|---|
| 前端薄、服务端权威 | 客户端定期轮询一个「全量状态」接口，收到后覆盖式渲染 | **最优**：只需实现那一个接口就能让官方前端动起来 |
| 前端厚、本地演算 | 客户端自己做动画与判定，服务端只存结果 | 需要逐个复刻客户端的指令契约 |

判断方法：在压缩 JS 里找轮询定时器（`setInterval`）指向的接口。
若客户端某个 `ObjUpdate/ApplyState` 类函数用服务端字段**直接覆盖**本地属性，就是第一类。

> 实战经验：若是第一类，**不要**去重写前端。复用官方前端 + 本地桩服务，
> 你只需要保证「接口返回格式」和「状态正确」，UI 与交互全部白拿。

## 五阶段流程

### 阶段 1：摸清入口与边界（只读）

1. 抓登录页，记录表单 `action`、字段名、是否有 CSRF / 密码是否 md5。**表单字段名后面要用**。
2. 登录（本人账号），记录 Set-Cookie；区分哪些 cookie 是会话、哪些是业务状态。
3. 找到「大厅 → 房间 → 客户端」的跳转链，记录每一步的 302 与所需参数。
4. 有 HAR 的话，先做**接口聚合统计**（按 host+path 计数），
   出现频次高的必然是轮询接口，那才是状态权威。

### 阶段 2：解析客户端，提取接口契约

对压缩 JS 的做法（**不要**试图美化整个文件，代价太大）：

1. 正则列出所有 `.asp` / API 路径的引用与出现次数。
2. 对每个路径，抽取**调用点前后 200 字符**作为上下文。
3. 重点看 `success:` 回调——**这才是契约**。记录：
   - 返回值是字符串还是 JSON？分隔符是什么？字段顺序？
   - 成功/失败的判据（返回空串算成功？非空算成功？）
   - 单位（是秒还是毫秒？是格还是像素？）
4. 对关键函数按名字做**花括号配对抽取**，落成单独文件再读。

**必查的坑：jQuery 的 `datatype` 拼写**
老代码常写成 `datatype:"json"`（小写 t，无效选项）。jQuery 会忽略它并按 `Content-Type`
智能猜测。所以桩服务**统一返回 `text/html`**，客户端就会拿到原始字符串；
若返回 `application/json`，客户端会拿到对象，`a.split()` 直接崩。

### 阶段 3：抓真实数据（进房）

按阶段 1 记录的链路进房，把只读接口全部落盘：地图、单位、城市、会话参数、配置脚本。
**注意会话流程**：Classic ASP 站点常常必须**按顺序**走完
`保存 → 跟随 302 → 传输页 → 主页 → 业务接口`，少一步就返回会话失效标记。

### 阶段 4：搭离线桩服务

1. 镜像前端静态资源 + 一个本地 HTTP 服务。
2. `.asp` 一律返回 GBK 字节 + `charset=gbk`（见 references/encoding.md）。
3. 静态文件**按每个文件的真实编码**声明 charset（同一站点常混用 GBK/UTF-8）。
4. 写裁决引擎，逐步替换桩：先 `ObjAjax`（状态），再时钟，再指令，最后射击。

### 阶段 5：验证

**两级验证，缺一不可**：

- **单元自检**：几何往返、邻接距离、通视、机动耗时、裁决抽样。
  自检要能**发现自己的 bug**——例如"往返不一致""邻接距离不为 1"这种断言。
- **端到端**：写脚本**完全按客户端 HTTP 契约**打自己的桩服务，
  走一遍机动（含返回耗时、状态更新）与射击（含战果下发）。

最后一定要在浏览器里目视确认。

## 高频陷阱清单

详细展开见 `references/pitfalls.md`，这里只列最要命的：

1. **JS `Math.round` ≠ Python `round`**：JS 是半值向上，Python 是银行家舍入。
   移植坐标换算时差一格，整个几何全错。
2. **编码混用**：同一站点的 HTML/JS/CSS 可能部分 GBK、部分 UTF-8。
3. **日期字段被当成布尔用**：某字段既做"是否开始"的真值判断、
   又被拿去做日期差算时钟 → 必须填**日期串**，填 `1` 会显示 `NaN:NaN:NaN`。
4. **`Content-Type` 缺 charset** 时，浏览器回退到文档编码；显式声明错的 charset 比不声明更糟。
5. **射击特效接口**：返回的参数若指向不存在的 DOM，客户端会抛异常打断后续渲染。
   让它的"持续秒数"为 0，客户端就会走安全分支。
6. **抓包文件含会话信息**：绝不可提交、不可重放。

## 从手册重建裁决表

若规则在 PDF 手册里（这类手册几乎都是 PDF + 文本层）：

1. 先按页抽文本，判断有无文本层、乱码率。
2. **不要相信纯文本抽取的列结构**——宽表会错位。要么按词坐标聚类，
   要么直接用表格网格线（`page.edges`）重建。
3. 重建后用**领域不变量自检**：例如"攻击等级越高结果不应变差"（单调性）。
   违反单调性说明列对齐错了，可用单调性**反解**列偏移。
4. 仍然有歧义时，**老实标注**并把原始数据留在数据文件里供人工校正，
   不要假装已经还原成功。

## 法律与伦理边界

- 只使用**本人账号**，只做**正常登录与观察**，不绕过任何安全机制、不爆破、不越权。
- 抓到的会话信息、账号密码**永不**写进代码、日志、提交或对话。
- 客户端脚本、美术资源、手册的版权属于原厂商。**默认不进公开仓库**；
  仓库里只放**你自己的代码、文档与方法论**。
- 裁决表是功能性数据（数值），可为实现互操作性保留，但要在 `NOTICE` 里写清出处。
- 明确声明：复刻引擎与官方裁决**只有概率分布一致，单次结果不会相同**，不得用于作弊或冒名参赛。
