# 操控算子

## 何时用

要让 AI **指挥棋子**时：

- 给某个算子下达机动 / 射击 / 夺控 / 隐蔽命令
- 读取当前态势，判断"现在能做什么"
- 枚举合法动作、评估动作后果
- 跑多局对比不同打法，找好策略
- 作为 RL / LLM 规划器的交互环境

## 一、先跑通最小闭环

```python
import sys; sys.path.insert(0, ".")
from env import HexwarEnv

env = HexwarEnv(side="BLUE", fog=True)      # fog=True 是真实兵推，只有可见敌方
obs = env.reset(seed=1)

while not env.done:
    acts = env.legal_actions()               # 当前所有合法动作
    obs, reward, done, info = env.step(acts[0])
    print(env.render())                      # 文本态势，调试用
print(env.score())
```

命令行跑分台：

```bash
py -3.13 env/run_episode.py --agent greedy-multi --episodes 20 --render
py -3.13 env/run_episode.py --agent random --episodes 50 --side RED --json out.json
```

## 二、观察怎么读

`env.observe()` 返回纯 JSON：

| 字段 | 含义 | 用法 |
|---|---|---|
| `time` / `time_left` | 已推演秒数 / 剩余秒数 | **时间是资源**，别把时间花在无意义机动上 |
| `score` | `own/enemy` 各有 `remaining`(剩余兵力) `captured`(夺控) `killed`(歼敌) `total`，另有 `pending_rules` 列出未实测口径（现为空） | 决策的最终目标函数（**三项分值与夺控边界均已实测**，见 references/action-schema.md） |
| `objectives` | 夺控点：`pos` `hexid` `held_by` | `held_by != side` 的才是要抢的 |
| `own` | 己方全部算子（**完整信息**） | 含 `weapons` 弹药与射程 |
| `enemy_visible` | **当前可观察到的**敌方 | 只有这些能打 |
| `enemy_known` | 曾见过但已脱离观察的敌方 | **位置是过期的**（`stale: true`），别按它瞄准 |

**关键判读规则**

1. `enemy_visible` 为空 ≠ 敌人不存在，只说明你**看不见**（迷雾 + 通视 + 侦察距离）。
2. `enemy_known` 里的坐标是最后一次看到的，目标可能已移动。
3. 每个己方算子都带 `can_observe_range`（人员/车辆/空中的侦察距离），
   它决定了你能看见多远。
4. `suppressed=1` 的算子**不能机动也不能射击**，只能等压制解除（约 150 秒）。

坐标双写：`pos` 是内部格 ID（用于动作参数），`hexid` 是显示用行列号（用于人读与日志）。

## 三、动作空间

每个动作都是 `{"type": ..., ...}` 的 JSON。**实现时照抄这个表**。

| 动作 | 参数 | 前置条件 | 耗时 |
|---|---|---|---|
| `move` | `unit`, `path`(格 ID 数组，**含起点**) | 每格可通行、不超堆叠、非禁行 | 按地形与坡度累加 |
| `attack` | `unit`, `target`, `weapon`, `track`(0/1) | 射程内 + 通视 + 可观察 + 有弹药 | 10 s |
| `area_fire` | `units`(多个), `target_hex`, `weapon` | 至少一个单位能打到该格；**目标离开该格即失败** | 10 s |
| `stop_attack` | `unit` | 该单位已设定打击目标 | 0 s |
| `capture` | `unit` | 站在夺控点上，且该格与相邻 6 格**无敌方地面单位** | 30 s |
| `hide` | `unit`, `on`(0/1) | 非打击间隔期 | 10 s |
| `stop` | `unit` | – | 0 s |
| `wait` | `seconds` | – | 指定秒数 |
| `load` | `unit`(人员), `carrier`(车辆) | 两者**同格**、均未被压制、载员未满 | 30 s |
| `unload` | `unit`(车辆) | 车辆未被压制（被压制时车内人员不能下车） | 30 s |
| `grenade` | `unit`(人员), `target_hex` | 单位带手雷、弹药>0、未被压制；限本格或相邻格 | 10 s |

**上车后注意**：已上车的步兵**不能再单独下令**（移动/射击/隐蔽都不行），
它随载具机动，也**不占堆叠名额**、不单独参与同格交战。要让它独立行动先 `unload`。
下车由**车辆**下达（手册 3.3）。

**批量下达**：`env.step([a1, a2, a3])` 一次给多个算子下令，时间取其中最大值。
这比逐个 step 更接近真实指挥，也更快。

**两种战斗模式（容易混，务必分清）**：

| 模式 | 写法 | 跟踪目标？ | 何时用 |
|---|---|---|---|
| 单次射击 | `track: 0`（默认） | — | 只想打一发 |
| **持续打击** | `track: 1` | **跟**，直到目标被消灭 | 官方默认语义（手册 3.14）。**设一次就放手**，之后用别的 step 去做机动 |
| **集火射击** | `area_fire` | **不跟**，锁的是**格** | 多个算子打同一格（手册 3.16）。目标挪走就白打 |

**持续打击是省时间的关键**：设定后无需重复下令，时间可以用来机动或捕别的目标。
但要记住它会**自动消耗时间并开火**；不想要了用 `stop_attack` 解除。

**动作从哪来**：务必用 `env.legal_actions()` 枚举，不要自己拼。
它已经做了通行、堆叠、射程、通视、观察、压制、弹药的全部校验。
`move_radius` 控制机动枚举半径（默认 6 格），太大会动作爆炸。

## 三·补、官方完整指令词汇（从客户端脚本实测抽取）

上面的 `move/attack/...` 是本环境**抽象后**的动作。官方客户端真正的指令体是：


| `weapon` | 选择武器 | 隐含在 `attack.weapon` |

## 四、规则约束速查（"能不能做"）

| 想做 | 约束 |
|---|---|
| 机动 | 禁行格(`step=0`)不可进入；车辆不可跨过河/水系；车辆遇高差过大不可通过；同格本方地面算子 **≤4** |
| 机动（人员） | 不受居民地/丛林影响；过河速度减半；坡度≥4 级减半 |
| 冲锋（人员） | 4 倍速，但**每冲锋 200 米（即 1 格）就转疲劳**；疲劳后**不能再冲锋**，只能普通机动；停止机动并等一个疲劳时长后解除 |
| 机动（车辆） | 丛林 ×1/2、居民地 ×1/3；**高差 >100 米不可进入**；坡度每 20 米一级，速度按级数递增 |
| 被压制 | **不能机动**（`step_seconds` 直接拒绝）、不能射击；机动中被压制则停下，解压制后可继续原命令 |
| 射击 | 需**同时**满足：距离 ≤ 武器射程、连线通视、目标可观察、弹药 > 0、射击方未被压制 |
| 射击（战果互斥） | 对**人员**：消灭班数与压制**互斥**；对**车辆**：只要有有效战果就**同时**压制（含被防护力修正为 0 的情况） |
| 手雷 | 对**格内所有人员（含己方）**各裁决一次；**打不到空中单位和掩体**；裁决有效则掉 1 个班且剩余被压制 |
| 射击（反无人机） | 只有防空类武器能打空中单位；**巡飞弹不可被任何武器打击** |
| 夺控 | 空中单位与炮兵**不能**夺控；本格与相邻 6 格无敌方地面单位 |
| 隐蔽 | 被观察距离减半；但**打击间隔期内不允许隐蔽**；已压制者再被裁决压制会掉 1 兵力 |
| 同格交战 | 进入敌方地面单位所在格**自动触发**；被攻击者自动还击，攻击间隔为正常的 **1/3**（本环境 = 3 秒） |
| 侦察（无人机） | 对暴露地面目标 400 米；**掩蔽中的车辆不减半**，掩蔽中的**人员减半** |

**战果修正的直觉**（影响你怎么打）：

- **不利**：射击方在机动中、被压制；目标在掩蔽/机动中/卧倒
- **有利**：目标处于堆叠状态；居高临下（但要真正通视）
- **地形**：居民地 −1、丛林地 −2、工事/掩体 −4（打掩体里的目标非常难）

## 五、战术原语

不要每次从零"思考"，先用这些可复用的决策模式：

1. **抢点**：优先级最高。`capture` 的收益是直接进总分的，且可能触发胜利条件。
   走之前先确认"目标格 + 相邻 6 格"有没有敌人，否则白跑。
2. **火力集中**：优先打**同一目标**直到消灭，而不是分散打多个。
   因为分值乘在**兵力**上（`Σ score×blood`，已实测），**打残就已在得分**——
   但歼灭分具体怎么算尚未确证，所以“整单位消灭才算分”不能当结论。
3. **先敌发现**：侦察距离决定交火主动权。无人机/巡飞弹侦察距离短但能前出；
   己方主力的 `can_observe_range` 通常远大于武器射程，**看得见就能打**。
4. **压制换时间**：即使打不出战果，"压制"也能让对手一整个回合无法行动。
   用便宜武器压制高价值目标，性价比常常高于硬拼。
5. **利用地形**：让目标待在居民地/丛林里（对自己不利时要机动出去），
   或退到掩体后——修正值很可观。
6. **别浪费弹药**：有限弹药（如拦截弹、导弹）不要打不值钱的目标。
7. **时间预算**：`time_left` 是硬约束。机动耗时随地形陡增（车辆爬坡 ×2/×3/禁止），
   算好"能不能在结束前到位"，否则这局等于没动。

## 六、策略搜索工作流

```python
from env import HexwarEnv
from env.agents import GreedyAgent

def evaluate(policy_fn, episodes=30, side="BLUE", snap=None):
    diffs = []
    for s in range(episodes):
        env = HexwarEnv(snapshot=snap, side=side, fog=True)
        obs = env.reset(seed=s)
        while not env.done:
            obs, r, done, info = env.step(policy_fn(env, obs))
        diffs.append(env.score()["diff"])
    return sum(diffs) / len(diffs), sum(d > 0 for d in diffs) / len(diffs)
```

**做实验的规矩**

1. **固定随机种子集合**，同一套种子跑不同策略才能比。
2. 先跟 `random` 基线比，再跟 `greedy-multi` 比。
3. 至少 20 局，看**均值 + 胜率**，不要看单局。
4. 改一个变量再跑，不要同时改三处。
5. 用 `--json` 落盘，便于回看。

**给 LLM 做规划器的提示词骨架**

```
你是蓝方指挥。下面是当前态势 JSON 与可用动作列表 JSON。
请只输出一个 JSON 动作（或动作数组）。要求：
- 只能使用列表里出现过的动作，参数原样复制
- 优先夺控；其次集中火力消灭单个目标
- 被压制的算子不要下令
- 说明你这一步的意图（一行）
```

## 七、常见错误

| 错误 | 症状 | 修法 |
|---|---|---|
| 自己拼 `path` 忘了带起点 | 机动被拒或耗时多算一格 | 用 `legal_actions()` 给的动作原样提交 |
| 按 `enemy_known` 瞄 | 射程判定失败 / 打空 | 只用 `enemy_visible` 里的目标 |
| 对空武器打巡飞弹 | 恒定无效 | 巡飞弹免疫一切武器 |
| 打掩体里的目标 | 战果长期为 0 | 换目标，或用面杀伤/压制 |
| 被压制的算子下令 | 动作全失败、时间白流 | 先查 `suppressed` |
| 一步走满 6 格 | 时间被一口气吃掉，后续没时间 | 拆成逐步下达，边打边走 |
| 忽略 `time_left` | 结算时净胜分为负 | 把时间当预算做规划 |

## 八、备选：通过官方界面操控

若想**用鼠标操作**官方前端（人工校正、演示、录制）：

1. 点算子选中 → 右键出指令菜单 → 画路径 → 确认输入指令
2. 界面把指令编码成 JSON 提交，格式与上面的动作表同构
3. 界面会**实时校验**（通行/堆叠/通视），被拒时会弹提示并回滚
